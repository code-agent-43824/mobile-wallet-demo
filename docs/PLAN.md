# План — проверки после выпуска v1.60

Текущий этап: закрыть программные и симуляторные вопросы, не запуская проверки на реальном
телефоне. Изменения кода WalletConnect ведёт другой агент; результаты ручных запусков вносить в
[`device-test-matrix.md`](device-test-matrix.md), состояние проекта — в [`STATUS.md`](STATUS.md).

- [x] **coding-agent — сохранность кошелька.** Расширить сценарий CI: создать кошелёк с
  настоящим платформенным хранилищем, завершить процесс, запустить приложение снова и сравнить
  публичный адрес. Выполнить на доступной настольной платформе; подключить к smoke iOS-симулятора
  и настольных целей. Не использовать физический телефон и не менять WalletConnect.
- [x] **coding-agent — запуск с Xcode 27.** Подготовить отдельную команду для Mac, которая проверяет
  выбранный Xcode, создаёт изолированный симулятор, запускает smoke и сохраняет логи для владельца.
- [x] **coding-agent — iOS-симулятор с Xcode 27.** Добавить ручной GitHub Actions workflow
  на раннере `xcode-27`, запустить там `scripts/smoke/xcode27_simulator.sh`, проверить логи и
  записать версию Xcode, симулятор, результат и ссылку на свидетельство в строку v1.58 матрицы.
- [ ] **Предложение coding-agent — полный smoke без выпуска.** Вручную запустить `ci.yml` с
  `smoke=true` на `main`, прочитать логи запуска релизных сборок и обеих фаз сохранности кошелька
  на iOS-симуляторе, macOS, Windows и Linux; отдельно сверить существующий сценарий создания на
  Android-эмуляторе. Записать результаты и ограничения по каждой цели; не считать симулятор или
  настольный компьютер проверкой физического телефона.
- [ ] **Предложение coding-agent — PIN-блокировка на реальном хранилище.** После полного smoke
  расширить изолированный сценарий iOS-симулятора: включить запрос PIN при открытии, завершить
  процесс, убедиться в блокировке после запуска, проверить неверный и верный PIN и прежний адрес.
  Widget-тест уже покрывает эту логику с `InMemorySecureKeyValueStore`; цель здесь — проверить
  платформенное хранилище и границу процесса.
- [~] **Другой агент — WalletConnect.** Разобрать результаты уже запущенных тестов с реальным

  историческим наблюдением, пока повторный прогон не доказал исправление.
- [ ] После результатов WalletConnect согласовать матрицу, `STATUS.md` и следующий план;
